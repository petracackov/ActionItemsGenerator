# API

Base URL (v1): `http://localhost:8000`. Interactive docs when the server runs: `http://localhost:8000/docs`.

Errors: [ErrorHandling.md](ErrorHandling.md). Overview: [Architecture.md](Architecture.md).

---

## Types

### Note

```json
{
  "id": "6f1c2d4e-…",
  "text": "weekly sync tues\n- deploy went out friday...",
  "created_at": "2026-11-19T10:42:00Z",
  "action_items": [ActionItem, …]
}
```

| Field | Type | Rule |
|---|---|---|
| `id` | string (UUID) | Generated by the server. |
| `text` | string | The raw notes as submitted. |
| `created_at` | string | ISO 8601, UTC. |
| `action_items` | array of `ActionItem` | Can be empty. |

### ActionItem

```json
{
  "id": "a91e5b7c-…",
  "text": "Look into the retry logic / connection pool causing customer timeouts",
  "assignee": "Ana",
  "due": null,
  "done": false
}
```

| Field | Type | Rule |
|---|---|---|
| `id` | string (UUID) | Generated by the server. |
| `text` | string | Required, 1–500 characters. What needs to be done. |
| `assignee` | string or `null` | Who has to do it, as written in the notes ("Ana"). `null` when nobody is named. Never guessed. |
| `due` | string or `null` | As written ("Friday", "next week"). `null` if not mentioned. |
| `done` | bool | `false` on creation. The only field that can change. |

Keys are snake_case. Swift: `keyDecodingStrategy = .convertFromSnakeCase`, `dateDecodingStrategy = .iso8601`.

## Endpoints

### `GET /health`

Liveness check: proves the server is up.

**Response: `200 OK`**
```json
{ "status": "ok" }
```

### `POST /notes/extract`

Submit raw notes. Returns the saved note with its extracted action items.

**Request**
```json
{ "text": "weekly sync tues\n- deploy went out friday..." }
```

**Response: `201 Created`** returns a `Note`.

```json
{
  "id": "6f1c2d4e-…",
  "text": "weekly sync tues\n- deploy went out friday...",
  "created_at": "2026-11-19T10:42:00Z",
  "action_items": [
    { "id": "a91e…", "text": "Look into the retry logic / connection pool causing customer timeouts", "assignee": "Ana", "due": null, "done": false },
    { "id": "b22f…", "text": "Sort out laptop for the new starter", "assignee": null, "due": null, "done": false },
    { "id": "c37a…", "text": "Get an answer from marketing on billing page copy", "assignee": "Marko", "due": "Friday", "done": false }
  ]
}
```

`action_items` can be empty if the notes contain none.

### `GET /notes`

All notes with their items, newest first.

**Response: `200 OK`**
```json
{ "notes": [Note, …] }
```

Wrapped in an object so fields such as paging can be added later without breaking clients.

### `PATCH /items/{id}`

Mark an item done or undone. `done` is the only accepted field.

**Request**
```json
{ "done": true }
```

**Response: `200 OK`** returns the updated `ActionItem`.

## LLM output schema (internal)

What the backend asks Groq to return and validates before saving. Clients never see it.

```json
{ "action_items": [ { "text": "...", "assignee": "Ana", "due": null } ] }
```

- Requested via Groq's **strict Structured Outputs** (guarantees this exact shape) if the chosen model supports it, otherwise JSON mode (guarantees valid JSON only). The model is picked by measured latency against the 2s goal.
- The root is an object, which both modes require.
- The model only produces `text`, `assignee` and `due`. The server adds `id`, `done` and `created_at`, so the model can't mark items done or invent IDs.
- Validated against the rules above. Anything invalid discards the whole submission (see [ErrorHandling.md](ErrorHandling.md#3-groqs-response)).
